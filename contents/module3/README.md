# BIO 2110 — Module 3 repository content

Searching text with `grep` and basic regular expressions.

Built 20 September 2026 to match what the live OpenLab pages actually ask
students to run. Every command on the chapter, lab and practice assignment
pages was executed against these files before this was packaged.

## Why some data is committed and some is generated

Module 3 runs on two platforms, and they need opposite things.

**Binder, for the book chapter.** Binder builds straight from this repository
and drops the reader into a terminal. A reader following the chapter must find
the data already there — the chapter says so in as many words: "In this Binder
environment, the Module 3 practice files are already prepared for you." So the
chapter's data is **committed as real files**, not generated. Nothing to run.

**Google Cloud Shell, for the lab and the practice assignment.** Students clone
the repository and run a setup script, as they have since Module 1. Those two
workspaces are **generated by scripts**, so a student who ruins a file restores
it by running the script again.

## Two things worth knowing before you teach from this

**`medical_chart.txt` exists twice.** The chapter runs
`grep -n 'Diabetes' medical_chart.txt` with no folder in front of it, and it
also refers to `examples/` and `../examples/`. Binder opens at
`contents/module3/`, so the bare command only works if the file is at the module
root. It is in both places so the chapter works exactly as written. If you would
rather keep one copy, change the chapter command to
`grep -n 'Diabetes' examples/medical_chart.txt` and delete the root copy.

**`clinical/patients.csv` is one column.** The lab anchors patterns to whole
lines (`^P[0-9]{3}$`). On a multi-column CSV every one of those drills returns
nothing, because the line is `P001,Alvarez,...` and never just `P001`. It is a
single-column list so the anchored patterns do what the lab says they do. The
list mixes 23 well-formed ids with 10 near misses (`P0007`, `P9999`,
`P9999999`, `P07`, `P7`, `PATIENT001`, `p001`, `0007P`, `12345`, `P001A`), and
two of those start with a digit so `^[0-9]` and `^[^0-9]` both find something.

`grep 'Glucose'` 15 and `grep -i 'glucose'` 16, so the `-i` lesson has
